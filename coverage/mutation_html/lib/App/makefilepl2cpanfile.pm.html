  136: =head1 DESCRIPTION
  137: 
  138: A Perl distribution lists the modules it needs in its F<Makefile.PL>.
  139: Many tools (for example C<cpanm --installdeps .> and CI systems) prefer
  140: a F<cpanfile> instead.  This module reads a F<Makefile.PL> and writes the
  141: same list in F<cpanfile> form, so you only keep the list in one place.
  142: 
  143: The F<Makefile.PL> is B<never run>.  It is read as plain text and
  144: searched for the parts that list dependencies.  This makes the tool safe
  145: to use on code you do not trust, but it also means that it cannot see
  146: dependencies that are computed while the program runs (see
  147: L</COMMON PITFALLS>).
  148: 
  149: =head2 What it reads
  150: 
  151: =over 4
  152: 
  153: =item * C<PREREQ_PM>, C<BUILD_REQUIRES>, C<TEST_REQUIRES> and
  154: C<CONFIGURE_REQUIRES>.  These become C<requires> lines in the C<runtime>,
  155: C<build>, C<test> and C<configure> phases.
  156: 
  157: =item * C<prereqs =E<gt> { PHASE =E<gt> { RELATIONSHIP =E<gt> { ... } } }>
  158: blocks (the CPAN::Meta::Spec version 2 layout), wherever they appear -
  159: also inside C<META_MERGE>.
  160: 
  161: =item * C<recommends =E<gt> { ... }> and C<suggests =E<gt> { ... }>
  162: directly inside C<META_MERGE> (the older version 1 layout).  These become
  163: C<recommends> and C<suggests> lines in the C<runtime> phase.
  164: 
  165: =item * C<MIN_PERL_VERSION>, which becomes C<requires 'perl', 'VERSION';>.
  166: 
  167: =item * A C<#> comment after an entry.  It is copied to the F<cpanfile>.
  168: 
  169: =back
  170: 
  171: =head2 What it writes
  172: 
  173: 	# Generated from Makefile.PL using makefilepl2cpanfile

  175: 	requires 'perl', '5.010';

  190: phases follow in this order: C<configure>, C<build>, C<test>, C<develop>.
  191: Inside each phase, C<requires> lines come first, then C<recommends>, then
  192: C<suggests>, and the modules are in alphabetical order.  The same input
  193: always gives exactly the same output.

  195: =head1 CONFIGURATION
  196: 
  197: When C<with_develop> is true (the default), some developer tools are
  198: added to the C<develop> phase.  By default these are L<Devel::Cover>,
  199: L<Perl::Critic>, L<Test::Pod> and L<Test::Pod::Coverage>.
  200: 
  201: To choose your own list, create the file
  202: F<~/.config/makefilepl2cpanfile.yml>:
  203: 
  204: 	develop:
  205: 	  Perl::Critic: 0
  206: 	  Devel::Cover: 0
  207: 	  My::Extra::Tool: '1.00'
  208: 
  209: The number after each name is the minimum version; C<0> means "any
  210: version".  Your list B<replaces> the default list; it is not added to it.
  211: Names that are not valid module names, and versions that are not version
  212: numbers, are ignored with a warning, so a mistake in this file can never
  213: put unexpected code into your F<cpanfile>.

  216: 
  217: C<parse_prereqs()> returns a hash reference with three levels:
  218: 
  219: 	{
  220: 		PHASE => {
  221: 			RELATIONSHIP => {
  222: 				'Module::Name' => { version => '1.0', comment => 'why it is needed' },
  223: 			},
  224: 		},
  225: 	}

  228: 
  229: =item * PHASE is one of C<runtime>, C<configure>, C<build>, C<test> or
  230: C<develop>.
  231: 
  232: =item * RELATIONSHIP is one of C<requires>, C<recommends> or C<suggests>.
  233: 
  234: =item * C<version> is the minimum version exactly as it was written (for
  235: example C<'1.60'> stays C<'1.60'>).  It is C<0> when there is no minimum.
  236: 
  237: =item * C<comment> is the text of the C<#> comment after the entry, or
  238: C<undef> when there is none.
  239: 
  240: =back
  241: 
  242: A phase or relationship with no modules is not present at all.

  244: =head1 ENCODING
  245: 
  246: =over 4
  247: 
  248: =item * B<The Makefile.PL file> is read as UTF-8.  Comments may contain
  249: any printable Unicode text, including accented letters, emoji and
  250: combining marks; they are copied to the output unchanged.  Control
  251: characters (other than TAB) and Unicode direction-override characters
  252: are removed from comments, so that the generated file cannot be made to
  253: look different from what it really contains.  If the file is not valid UTF-8 you get a
  254: warning and processing continues (see L</generate(%args)>).
  255: 
  256: =item * B<The returned cpanfile text> is a Perl character string.  Write
  257: it with a UTF-8 output layer, for example C<path(...)-E<gt>spew_utf8> or
  258: C<binmode $fh, ':encoding(UTF-8)'>.  Otherwise Perl warns
  259: "Wide character in print" when a comment contains non-ASCII text.
  260: 
  261: =item * B<The existing argument> and B<the content argument of
  262: parse_prereqs()> must be character strings: decode them first (for
  263: example with C<slurp_utf8>).  Raw bytes work for plain ASCII, but a
  264: non-ASCII comment would come back as separate bytes.
  265: 
  266: =item * B<Module names> must be plain ASCII (A-Z, a-z, 0-9, C<_> and
  267: C<::>), as CPAN requires.  A name with any other character is ignored.
  268: This also stops look-alike names, such as C<Test::More> written with a
  269: Cyrillic letter.
  270: 
  271: =item * B<Version numbers> may use only the ASCII digits 0-9, C<.>,
  272: C<_> and a leading C<v>, and must contain at least one digit.  The whole
  273: value is checked: C<'1.0-TRIAL'> is not shortened to C<'1.0'>.  Anything
  274: else is treated as "no minimum version".
  275: 
  276: =item * B<The YAML configuration file> is read as UTF-8; the same rules
  277: for names and versions apply.
  278: 
  279: =item * B<File names> are passed to the operating system unchanged.
  280: Names with spaces, non-ASCII letters or shell characters such as C<;>
  281: and C<|> are safe: no shell is ever used.
  282: 
  283: =back

  285: =head1 COMMON PITFALLS
  286: 
  287: =over 4
  288: 
  289: =item * B<Code in Makefile.PL is not run.>  Dependencies that are built
  290: by code are not seen, for example C<PREREQ_PM =E<gt> \%deps> or a list
  291: returned by a function.  Entries inside a condition, such as
  292: C<$^O eq 'MSWin32' ? ('Win32' =E<gt> 0) : ()>, are seen but become
  293: unconditional.  Write such dependencies as plain entries, or add them to
  294: the F<cpanfile> another way.
  295: 
  296: =item * B<Only the develop section of an existing cpanfile is kept.>
  297: Hand edits anywhere else (for example a C<feature> block or an extra
  298: C<on 'test'> line) are lost when you regenerate.  Put hand-written
  299: entries in C<on 'develop' =E<gt> sub { ... }>.
  300: 
  301: =item * B<Conditions inside the kept develop section are removed.>  An
  302: C<if (...) { requires 'X' }> inside the develop block is carried over as
  303: a plain C<requires 'X'>.  Comments in the develop block are not kept.
  304: 
  305: =item * B<Which entry wins.>  When the same module is listed twice in the
  306: same phase and relationship, the first one wins.  The simple keys
  307: (C<PREREQ_PM> and friends) are read before C<prereqs> blocks, and entries
  308: from F<Makefile.PL> win over entries in the existing develop section.
  309: The same module under two different relationships (for example
  310: C<requires> and C<recommends>) is kept twice.
  311: 
  312: =item * B<The configuration file replaces the default tools.>  If you
  313: list only C<My::Tool>, then C<Perl::Critic> and the others are no longer
  314: added.  List them too if you want them.
  315: 
  316: =item * B<undef means "use the default".>  C<makefile =E<gt> undef> reads
  317: F<Makefile.PL>; C<existing =E<gt> undef> is the same as C<''>; and
  318: C<with_develop =E<gt> undef> means B<true>.  Use C<with_develop =E<gt> 0>
  319: to turn developer tools off.
  320: 
  321: =item * B<parse_prereqs(undef) is silent.>  It returns an empty hash
  322: reference with no warning, so a failed file read can look like "no
  323: dependencies".  Check that the read worked before you call it.
  324: 
  325: =item * B<The output depends on who runs it.>  With C<with_develop> on,
  326: the tool list comes from the home directory of the current user.  Use
  327: C<with_develop =E<gt> 0> when every computer must produce the same file.
  328: 
  329: =item * B<generate() does not write any file.>  It returns the text.
  330: Save it yourself (see L</SYNOPSIS>) or use the command-line tool.
  331: 
  332: =item * B<Relative paths> in C<makefile> are relative to the current
  333: working directory, not to your script.
  334: 
  335: =item * B<Warnings are not errors.>  Problems such as invalid UTF-8 or a
  336: bad configuration entry are reported with C<warn> (through L<Carp>) and
  337: processing continues.  Catch them with C<$SIG{__WARN__}> if you need to
  338: act on them.
  339: 
  340: =back

  342: =head1 METHODS
  343: 
  344: =head2 generate(%args)
  345: 
  346: =head3 PURPOSE
  347: 
  348: Reads a F<Makefile.PL> and returns the text of a matching F<cpanfile>.
  349: The F<Makefile.PL> is read as text and is never run.
  350: 
  351: =head3 ARGUMENTS
  352: 
  353: Give the arguments as a list of name/value pairs, or as one hash
  354: reference.  All of them are optional.
  355: 
  356: =over 4
  357: 
  358: =item * C<makefile> - the path of the F<Makefile.PL> to read.  Default:
  359: C<'Makefile.PL'> in the current directory.  Anything that turns into a
  360: path when used as a string is accepted, such as a L<Path::Tiny> object.
  361: A filehandle or another kind of reference is refused with
  362: C<Cannot read>.
  363: 
  364: =item * C<existing> - the text of your current F<cpanfile>.  Default:
  365: C<''> (none).  Only its C<on 'develop' =E<gt> sub { ... }> section is
  366: used.  Every C<requires>, C<recommends> and C<suggests> line in that
  367: section is copied to the new text, so your hand-written developer
  368: dependencies are kept.  Lines that are commented out are not copied.
  369: An entry whose name is not a valid module name is dropped.  An entry
  370: whose version is not a version number is kept without a version, and
  371: you get a warning.
  372: 
  373: =item * C<with_develop> - true or false.  Default: true.  When true, the
  374: developer tools from the configuration file (see L</CONFIGURATION>), or
  375: the default tools, are added to the C<develop> phase as C<requires>.  A
  376: tool that is already in the develop phase, from the F<Makefile.PL> or
  377: from C<existing>, is left exactly as it is.
  378: 
  379: =back
  380: 
  381: =head3 RETURNS
  382: 
  383: A string: the complete F<cpanfile>.  It always starts with the line
  384: C<# Generated from Makefile.PL using makefilepl2cpanfile> and always ends
  385: with exactly one newline.  The layout is described in
  386: L</What it writes>.  A F<Makefile.PL> with no dependencies gives just
  387: the first line.
  388: 
  389: =head3 SIDE EFFECTS
  390: 
  391: =over 4
  392: 
  393: =item * Reads the C<makefile> file.
  394: 
  395: =item * When C<with_develop> is true, reads
  396: F<~/.config/makefilepl2cpanfile.yml> if it exists.
  397: 
  398: =item * Never writes, creates or deletes any file.
  399: 
  400: =item * May print warnings (see MESSAGES below).
  401: 
  402: =item * Does not change the caller's C<$@>, C<$!> or C<$_>.
  403: 
  404: =back
  405: 
  406: =head3 USAGE EXAMPLE
  407: 
  408: 	use App::makefilepl2cpanfile;
  409: 	use Path::Tiny;
  410: 
  411: 	my $cpanfile = path('cpanfile');
  412: 	my $text = App::makefilepl2cpanfile::generate(
  413: 		makefile     => 'Makefile.PL',
  414: 		existing     => $cpanfile->exists ? $cpanfile->slurp_utf8 : '',
  415: 		with_develop => 1,
  416: 	);

  419: =head3 HOW IT WORKS
  420: 
  421: =over 4
  422: 
  423: =item 1. Check that C<makefile> is a readable, regular file.
  424: 
  425: =item 2. Read it as UTF-8.  If that fails because of bad UTF-8, warn and
  426: read the raw bytes instead.  Any other read error is passed on.
  427: 
  428: =item 3. Find C<MIN_PERL_VERSION> and call L</parse_prereqs($content)>.
  429: 
  430: =item 4. Copy the develop entries from C<existing>, without replacing
  431: entries that came from the F<Makefile.PL>.
  432: 
  433: =item 5. If C<with_develop> is true, add each configured tool that is
  434: not already in the develop phase.
  435: 
  436: =item 6. Format and return the text.
  437: 
  438: =back
