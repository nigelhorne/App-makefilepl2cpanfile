  124: =head1 DESCRIPTION
  125: 
  126: A Perl distribution lists the modules it needs in its F<Makefile.PL>.
  127: Many tools (for example C<cpanm --installdeps .> and CI systems) prefer
  128: a F<cpanfile> instead.  This module reads a F<Makefile.PL> and writes the
  129: same list in F<cpanfile> form, so you only keep the list in one place.
  130: 
  131: The F<Makefile.PL> is B<never run>.  It is read as plain text and
  132: searched for the parts that list dependencies.  This makes the tool safe
  133: to use on code you do not trust, but it also means that it cannot see
  134: dependencies that are computed while the program runs (see
  135: L</COMMON PITFALLS>).
  136: 
  137: =head2 What it reads
  138: 
  139: =over 4
  140: 
  141: =item * C<PREREQ_PM>, C<BUILD_REQUIRES>, C<TEST_REQUIRES> and
  142: C<CONFIGURE_REQUIRES>.  These become C<requires> lines in the C<runtime>,
  143: C<build>, C<test> and C<configure> phases.
  144: 
  145: =item * C<prereqs =E<gt> { PHASE =E<gt> { RELATIONSHIP =E<gt> { ... } } }>
  146: blocks (the CPAN::Meta::Spec version 2 layout), wherever they appear -
  147: also inside C<META_MERGE>.
  148: 
  149: =item * C<recommends =E<gt> { ... }> and C<suggests =E<gt> { ... }>
  150: directly inside C<META_MERGE> (the older version 1 layout).  These become
  151: C<recommends> and C<suggests> lines in the C<runtime> phase.
  152: 
  153: =item * C<MIN_PERL_VERSION>, which becomes C<requires 'perl', 'VERSION';>.
  154: 
  155: =item * A C<#> comment after an entry.  It is copied to the F<cpanfile>.
  156: 
  157: =back

  161: 	# Generated from Makefile.PL using makefilepl2cpanfile

  178: phases follow in this order: C<configure>, C<build>, C<test>, C<develop>.
  179: Inside each phase, C<requires> lines come first, then C<recommends>, then
  180: C<suggests>, and the modules are in alphabetical order.  The same input
  181: always gives exactly the same output.

  269: =head1 COMMON PITFALLS
  270: 
  271: =over 4
  272: 
  273: =item * B<Code in Makefile.PL is not run.>  Dependencies that are built
  274: by code are not seen, for example C<PREREQ_PM =E<gt> \%deps> or a list
  275: returned by a function.  Entries inside a condition, such as
  276: C<$^O eq 'MSWin32' ? ('Win32' =E<gt> 0) : ()>, are seen but become
  277: unconditional.  Write such dependencies as plain entries, or add them to
  278: the F<cpanfile> another way.
  279: 
  280: =item * B<Only the develop section of an existing cpanfile is kept.>
  281: Hand edits anywhere else (for example a C<feature> block or an extra
  282: C<on 'test'> line) are lost when you regenerate.  Put hand-written
  283: entries in C<on 'develop' =E<gt> sub { ... }>.
  284: 
  285: =item * B<Conditions inside the kept develop section are removed.>  An
  286: C<if (...) { requires 'X' }> inside the develop block is carried over as
  287: a plain C<requires 'X'>.  Comments in the develop block are not kept.
  288: 
  289: =item * B<Which entry wins.>  When the same module is listed twice in the
  290: same phase and relationship, the first one wins.  The simple keys
  291: (C<PREREQ_PM> and friends) are read before C<prereqs> blocks, and entries
  292: from F<Makefile.PL> win over entries in the existing develop section.
  293: The same module under two different relationships (for example
  294: C<requires> and C<recommends>) is kept twice.
  295: 
  296: =item * B<The configuration file replaces the default tools.>  If you
  297: list only C<My::Tool>, then C<Perl::Critic> and the others are no longer
  298: added.  List them too if you want them.
  299: 
  300: =item * B<undef means "use the default".>  C<makefile =E<gt> undef> reads
  301: F<Makefile.PL>; C<existing =E<gt> undef> is the same as C<''>; and
  302: C<with_develop =E<gt> undef> means B<true>.  Use C<with_develop =E<gt> 0>
  303: to turn developer tools off.
  304: 
  305: =item * B<parse_prereqs(undef) is silent.>  It returns an empty hash
  306: reference with no warning, so a failed file read can look like "no
  307: dependencies".  Check that the read worked before you call it.
  308: 
  309: =item * B<The output depends on who runs it.>  With C<with_develop> on,
  310: the tool list comes from the home directory of the current user.  Use
  311: C<with_develop =E<gt> 0> when every computer must produce the same file.
  312: 
  313: =item * B<generate() does not write any file.>  It returns the text.
  314: Save it yourself (see L</SYNOPSIS>) or use the command-line tool.
  315: 
  316: =item * B<Relative paths> in C<makefile> are relative to the current
  317: working directory, not to your script.
  318: 
  319: =item * B<Warnings are not errors.>  Problems such as invalid UTF-8 or a
  320: bad configuration entry are reported with C<warn> (through L<Carp>) and
  321: processing continues.  Catch them with C<$SIG{__WARN__}> if you need to
  322: act on them.
  323: 
  324: =back

  330: =head3 PURPOSE
  331: 
  332: Reads a F<Makefile.PL> and returns the text of a matching F<cpanfile>.
  333: The F<Makefile.PL> is read as text and is never run.
  334: 
  335: =head3 ARGUMENTS
  336: 
  337: Give the arguments as a list of name/value pairs, or as one hash
  338: reference.  All of them are optional.
  339: 
  340: =over 4
  341: 
  342: =item * C<makefile> - the path of the F<Makefile.PL> to read.  Default:
  343: C<'Makefile.PL'> in the current directory.  Anything that turns into a
  344: path when used as a string is accepted, such as a L<Path::Tiny> object.
  345: A filehandle or another kind of reference is refused with
  346: C<Cannot read>.
  347: 
  348: =item * C<existing> - the text of your current F<cpanfile>.  Default:
  349: C<''> (none).  Only its C<on 'develop' =E<gt> sub { ... }> section is
  350: used.  Every C<requires>, C<recommends> and C<suggests> line in that
  351: section is copied to the new text, so your hand-written developer
  352: dependencies are kept.  Lines that are commented out are not copied.
  353: An entry whose name is not a valid module name is dropped.  An entry
  354: whose version is not a version number is kept without a version, and
  355: you get a warning.
  356: 
  357: =item * C<with_develop> - true or false.  Default: true.  When true, the
  358: developer tools from the configuration file (see L</CONFIGURATION>), or
  359: the default tools, are added to the C<develop> phase as C<requires>.  A
  360: tool that is already in the develop phase, from the F<Makefile.PL> or
  361: from C<existing>, is left exactly as it is.
  362: 
  363: =back
  364: 
  365: =head3 RETURNS
  366: 
  367: A string: the complete F<cpanfile>.  It always starts with the line
  368: C<# Generated from Makefile.PL using makefilepl2cpanfile> and always ends
  369: with exactly one newline.  The layout is described in
  370: L</What it writes>.  A F<Makefile.PL> with no dependencies gives just
  371: the first line.
  372: 
  373: =head3 SIDE EFFECTS
  374: 
  375: =over 4
  376: 
  377: =item * Reads the C<makefile> file.
  378: 
  379: =item * When C<with_develop> is true, reads
  380: F<~/.config/makefilepl2cpanfile.yml> if it exists.
  381: 
  382: =item * Never writes, creates or deletes any file.
  383: 
  384: =item * May print warnings (see MESSAGES below).
  385: 
  386: =item * Does not change the caller's C<$@>, C<$!> or C<$_>.
  387: 
  388: =back

  408:

  414: =item 4. Copy the develop entries from C<existing>, without replacing

  417: =item 5. If C<with_develop> is true, add each configured tool that is
  418: not already in the develop phase.
