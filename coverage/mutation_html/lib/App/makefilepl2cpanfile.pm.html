  138: =head1 DESCRIPTION
  139: 
  140: A Perl distribution lists the modules it needs in its F<Makefile.PL>.
  141: Many tools (for example C<cpanm --installdeps .> and CI systems) prefer
  142: a F<cpanfile> instead.  This module reads a F<Makefile.PL> and writes the
  143: same list in F<cpanfile> form, so you only keep the list in one place.
  144: 
  145: The F<Makefile.PL> is B<never run>.  It is read as plain text and
  146: searched for the parts that list dependencies.  This makes the tool safe
  147: to use on code you do not trust, but it also means that it cannot see
  148: dependencies that are computed while the program runs (see
  149: L</COMMON PITFALLS>).
  150: 
  151: =head2 What it reads
  152: 
  153: =over 4
  154: 
  155: =item * C<PREREQ_PM>, C<BUILD_REQUIRES>, C<TEST_REQUIRES> and
  156: C<CONFIGURE_REQUIRES>.  These become C<requires> lines in the C<runtime>,
  157: C<build>, C<test> and C<configure> phases.
  158: 
  159: =item * C<prereqs =E<gt> { PHASE =E<gt> { RELATIONSHIP =E<gt> { ... } } }>
  160: blocks (the CPAN::Meta::Spec version 2 layout), wherever they appear -
  161: also inside C<META_MERGE>.
  162: 
  163: =item * C<recommends =E<gt> { ... }> and C<suggests =E<gt> { ... }>
  164: directly inside C<META_MERGE> (the older version 1 layout).  These become
  165: C<recommends> and C<suggests> lines in the C<runtime> phase.
  166: 
  167: =item * C<MIN_PERL_VERSION>, which becomes C<requires 'perl', 'VERSION';>.
  168: 
  169: =item * A C<#> comment after an entry.  It is copied to the F<cpanfile>.
  170: 
  171: =back

  192: phases follow in this order: C<configure>, C<build>, C<test>, C<develop>.
  193: Inside each phase, C<requires> lines come first, then C<recommends>, then
  194: C<suggests>, and the modules are in alphabetical order.  The same input
  195: always gives exactly the same output.

  197: =head1 CONFIGURATION
  198: 
  199: When C<with_develop> is true (the default), some developer tools are
  200: added to the C<develop> phase.  By default these are L<Devel::Cover>,
  201: L<Perl::Critic>, L<Test::Pod> and L<Test::Pod::Coverage>.
  202: 
  203: To choose your own list, create the file
  204: F<~/.config/makefilepl2cpanfile.yml>:
  205: 
  206: 	develop:
  207: 	  Perl::Critic: 0
  208: 	  Devel::Cover: 0
  209: 	  My::Extra::Tool: '1.00'

  211: The number after each name is the minimum version; C<0> means "any
  212: version".  Your list B<replaces> the default list; it is not added to it.
  213: Names that are not valid module names, and versions that are not version
  214: numbers, are ignored with a warning, so a mistake in this file can never
  215: put unexpected code into your F<cpanfile>.

  218: 
  219: C<parse_prereqs()> returns a hash reference with three levels:
  220: 
  221: 	{
  222: 		PHASE => {
  223: 			RELATIONSHIP => {

  230: 
  231: =item * PHASE is one of C<runtime>, C<configure>, C<build>, C<test> or
  232: C<develop>.
  233: 
  234: =item * RELATIONSHIP is one of C<requires>, C<recommends> or C<suggests>.
  235: 
  236: =item * C<version> is the minimum version exactly as it was written (for
  237: example C<'1.60'> stays C<'1.60'>).  It is C<0> when there is no minimum.
  238: 
  239: =item * C<comment> is the text of the C<#> comment after the entry, or
  240: C<undef> when there is none.
  241: 
  242: =back
  243: 
  244: A phase or relationship with no modules is not present at all.

  246: =head1 ENCODING
  247: 
  248: =over 4
  249: 
  250: =item * B<The Makefile.PL file> is read as UTF-8.  Comments may contain
  251: any printable Unicode text, including accented letters, emoji and
  252: combining marks; they are copied to the output unchanged.  Control
  253: characters (other than TAB) and Unicode direction-override characters
  254: are removed from comments, so that the generated file cannot be made to
  255: look different from what it really contains.  If the file is not valid UTF-8 you get a
  256: warning and processing continues (see L</generate(%args)>).
  257: 
  258: =item * B<The returned cpanfile text> is a Perl character string.  Write
  259: it with a UTF-8 output layer, for example C<path(...)-E<gt>spew_utf8> or
  260: C<binmode $fh, ':encoding(UTF-8)'>.  Otherwise Perl warns
  261: "Wide character in print" when a comment contains non-ASCII text.
  262: 
  263: =item * B<The existing argument> and B<the content argument of
  264: parse_prereqs()> must be character strings: decode them first (for
  265: example with C<slurp_utf8>).  Raw bytes work for plain ASCII, but a
  266: non-ASCII comment would come back as separate bytes.
  267: 
  268: =item * B<Module names> must be plain ASCII (A-Z, a-z, 0-9, C<_> and
  269: C<::>), as CPAN requires.  A name with any other character is ignored.
  270: This also stops look-alike names, such as C<Test::More> written with a
  271: Cyrillic letter.
  272: 
  273: =item * B<Version numbers> may use only the ASCII digits 0-9, C<.>,
  274: C<_> and a leading C<v>, and must contain at least one digit.  The whole
  275: value is checked: C<'1.0-TRIAL'> is not shortened to C<'1.0'>.  Anything
  276: else is treated as "no minimum version".
  277: 
  278: =item * B<The YAML configuration file> is read as UTF-8; the same rules
  279: for names and versions apply.
  280: 
  281: =item * B<File names> are passed to the operating system unchanged.
  282: Names with spaces, non-ASCII letters or shell characters such as C<;>
  283: and C<|> are safe: no shell is ever used.
  284: 
  285: =back

  287: =head1 COMMON PITFALLS
  288: 
  289: =over 4
  290: 
  291: =item * B<Code in Makefile.PL is not run.>  Dependencies that are built
  292: by code are not seen, for example C<PREREQ_PM =E<gt> \%deps> or a list
  293: returned by a function.  Entries inside a condition, such as
  294: C<$^O eq 'MSWin32' ? ('Win32' =E<gt> 0) : ()>, are seen but become
  295: unconditional.  Write such dependencies as plain entries, or add them to
  296: the F<cpanfile> another way.
  297: 
  298: =item * B<Only the develop section of an existing cpanfile is kept.>
  299: Hand edits anywhere else (for example a C<feature> block or an extra
  300: C<on 'test'> line) are lost when you regenerate.  Put hand-written
  301: entries in C<on 'develop' =E<gt> sub { ... }>.
  302: 
  303: =item * B<Conditions inside the kept develop section are removed.>  An
  304: C<if (...) { requires 'X' }> inside the develop block is carried over as
  305: a plain C<requires 'X'>.  Comments in the develop block are not kept.
  306: 
  307: =item * B<Which entry wins.>  When the same module is listed twice in the
  308: same phase and relationship, the first one wins.  The simple keys
  309: (C<PREREQ_PM> and friends) are read before C<prereqs> blocks, and entries
  310: from F<Makefile.PL> win over entries in the existing develop section.
  311: The same module under two different relationships (for example
  312: C<requires> and C<recommends>) is kept twice.
  313: 
  314: =item * B<The configuration file replaces the default tools.>  If you
  315: list only C<My::Tool>, then C<Perl::Critic> and the others are no longer
  316: added.  List them too if you want them.
  317: 
  318: =item * B<undef means "use the default".>  C<makefile =E<gt> undef> reads
  319: F<Makefile.PL>; C<existing =E<gt> undef> is the same as C<''>; and
  320: C<with_develop =E<gt> undef> means B<true>.  Use C<with_develop =E<gt> 0>
  321: to turn developer tools off.
  322: 
  323: =item * B<parse_prereqs(undef) is silent.>  It returns an empty hash
  324: reference with no warning, so a failed file read can look like "no
  325: dependencies".  Check that the read worked before you call it.
  326: 
  327: =item * B<The output depends on who runs it.>  With C<with_develop> on,
  328: the tool list comes from the home directory of the current user.  Use
  329: C<with_develop =E<gt> 0> when every computer must produce the same file.
  330: 
  331: =item * B<generate() does not write any file.>  It returns the text.
  332: Save it yourself (see L</SYNOPSIS>) or use the command-line tool.
  333: 
  334: =item * B<Relative paths> in C<makefile> are relative to the current
  335: working directory, not to your script.
  336: 
  337: =item * B<Warnings are not errors.>  Problems such as invalid UTF-8 or a
  338: bad configuration entry are reported with C<warn> (through L<Carp>) and
  339: processing continues.  Catch them with C<$SIG{__WARN__}> if you need to
  340: act on them.
  341: 
  342: =back

  344: =head1 METHODS

  346: =head2 generate(%args)
  347: 
  348: =head3 PURPOSE
  349: 
  350: Reads a F<Makefile.PL> and returns the text of a matching F<cpanfile>.
  351: The F<Makefile.PL> is read as text and is never run.
  352: 
  353: =head3 ARGUMENTS
  354: 
  355: Give the arguments as a list of name/value pairs, or as one hash
  356: reference.  All of them are optional.
  357: 
  358: =over 4
  359: 
  360: =item * C<makefile> - the path of the F<Makefile.PL> to read.  Default:
  361: C<'Makefile.PL'> in the current directory.  Anything that turns into a
  362: path when used as a string is accepted, such as a L<Path::Tiny> object.
  363: A filehandle or another kind of reference is refused with
  364: C<Cannot read>.
  365: 
  366: =item * C<existing> - the text of your current F<cpanfile>.  Default:
  367: C<''> (none).  Only its C<on 'develop' =E<gt> sub { ... }> section is
  368: used.  Every C<requires>, C<recommends> and C<suggests> line in that
  369: section is copied to the new text, so your hand-written developer
  370: dependencies are kept.  Lines that are commented out are not copied.
  371: An entry whose name is not a valid module name is dropped.  An entry
  372: whose version is not a version number is kept without a version, and
  373: you get a warning.
  374: 
  375: =item * C<with_develop> - true or false.  Default: true.  When true, the
  376: developer tools from the configuration file (see L</CONFIGURATION>), or
  377: the default tools, are added to the C<develop> phase as C<requires>.  A
  378: tool that is already in the develop phase, from the F<Makefile.PL> or
  379: from C<existing>, is left exactly as it is.
  380: 
  381: =back
  382: 
  383: =head3 RETURNS
  384: 
  385: A string: the complete F<cpanfile>.  It always starts with the line
  386: C<# Generated from Makefile.PL using makefilepl2cpanfile> and always ends
  387: with exactly one newline.  The layout is described in
  388: L</What it writes>.  A F<Makefile.PL> with no dependencies gives just
  389: the first line.
  390: 
  391: =head3 SIDE EFFECTS
  392: 
  393: =over 4
  394: 
  395: =item * Reads the C<makefile> file.
  396: 
  397: =item * When C<with_develop> is true, reads
  398: F<~/.config/makefilepl2cpanfile.yml> if it exists.
  399: 
  400: =item * Never writes, creates or deletes any file.
  401: 
  402: =item * May print warnings (see MESSAGES below).
  403: 
  404: =item * Does not change the caller's C<$@>, C<$!> or C<$_>.
  405: 
  406: =back
  407: 
  408: =head3 USAGE EXAMPLE
  409: 
  410: 	use App::makefilepl2cpanfile;
  411: 	use Path::Tiny;
  412: 
  413: 	my $cpanfile = path('cpanfile');
  414: 	my $text = App::makefilepl2cpanfile::generate(
  415: 		makefile     => 'Makefile.PL',
  416: 		existing     => $cpanfile->exists ? $cpanfile->slurp_utf8 : '',

  421: =head3 HOW IT WORKS
  422: 
  423: =over 4
  424: 
  425: =item 1. Check that C<makefile> is a readable, regular file.
  426: 
  427: =item 2. Read it as UTF-8.  If that fails because of bad UTF-8, warn and
  428: read the raw bytes instead.  Any other read error is passed on.
  429: 
  430: =item 3. Find C<MIN_PERL_VERSION> and call L</parse_prereqs($content)>.
  431: 
  432: =item 4. Copy the develop entries from C<existing>, without replacing
  433: entries that came from the F<Makefile.PL>.
  434: 
  435: =item 5. If C<with_develop> is true, add each configured tool that is
  436: not already in the develop phase.
  437: 
  438: =item 6. Format and return the text.
  439: 
  440: =back

 1203: =head1 DESIGN NOTES
 1204: 
 1205: Some checks are made once, where data enters, and relied on afterwards.
 1206: Each rule below is proved by F<t/logic.t>.
 1207: 
 1208: =over 4
 1209: 
 1210: =item * B<Versions.>  Every version is checked when it is read (from the
 1211: F<Makefile.PL>, the existing F<cpanfile> or the configuration file) and
 1212: replaced by C<0> if it is not a version number.  A version number is
 1213: zero exactly when none of its digits is 1 to 9.  So, when the output is
 1214: written, "does it contain a digit from 1 to 9?" is the whole test for
 1215: whether to print a minimum version.
 1216: 
 1217: =item * B<Comments.>  An empty comment is stored as "no comment" when it
 1218: is read, and entries from other sources have no comment.  So, when the
 1219: output is written, a comment that exists is never empty and can be
 1220: printed without further checks.
 1221: 
 1222: =item * B<Developer tools.>  A tool must not be added if the develop
 1223: phase already lists it under any relationship.  So the set of listed
 1224: modules is built once, and every configured tool outside that set is
 1225: added.
 1226: 
 1227: =item * B<Order of checks.>  Each function stops at the first check that
 1228: fails: an unreadable F<Makefile.PL> is refused before anything is read,
 1229: and the configuration file is only parsed once it is known to exist and
 1230: to be a regular file.
 1231: 
 1232: =back

 1235: 
 1236: =over 4
 1237: 
 1238: =item * The F<Makefile.PL> is read with patterns, not run, so dependencies
 1239: that are computed by code cannot be found (see L</COMMON PITFALLS>).

 1358: =head1 STATE DIAGRAM
 1359: 
 1360: The module keeps no state between calls: every call starts at START and
 1361: ends at RETURN or at an error.  The diagram shows the states that one
 1362: call to C<generate()> passes through.  C<parse_prereqs()> is the single
 1363: step PARSE.
 1364: 
 1365: 	+-------+
 1366: 	| START |  generate(%args) is called
 1367: 	+-------+
 1368: 	    |
 1369: 	    | makefile is a readable regular file?
 1370: 	    |---- no ------------------------------------> [DIE] croak "Cannot read '...'"
 1371: 	    | yes
 1372: 	    v
 1373: 	+------------+  read as UTF-8
 1374: 	| READ_UTF8  |---- decode error --> +-----------+  carp "invalid UTF-8"
 1375: 	+------------+                      | READ_RAW  |  (read the raw bytes)
 1376: 	    |     \                         +-----------+
 1377: 	    |      \---- other I/O error --------------------------> [DIE] error passed on
 1378: 	    | ok                                 |
 1379: 	    v                                    |
 1380: 	+------------+ <-------------------------+
 1381: 	|   PARSE    |  parse_prereqs(content); find MIN_PERL_VERSION
 1382: 	+------------+  (pure: no I/O, no warnings)
 1383: 	    |
 1384: 	    | existing has an on 'develop' section?
 1385: 	    |---- no ----------------------------+
 1386: 	    | yes                                |
 1387: 	    v                                    |
 1388: 	+------------+  copy entries; drop       |
 1389: 	|   MERGE    |  bad names; carp and      |
 1390: 	+------------+  drop bad versions        |
 1391: 	    |                                    |
 1392: 	    +<-----------------------------------+
 1393: 	    |
 1394: 	    | with_develop true?
 1395: 	    |---- no ----------------------------------------------+
 1396: 	    | yes                                                  |
 1397: 	    v                                                      |
 1398: 	+------------+  no home dir, or config path missing        |
 1399: 	| CONFIG     |  or not a regular file -------> DEFAULTS    |
 1400: 	+------------+                                   |         |
 1401: 	    | config is a regular file                   |         |
 1402: 	    |---- stat/read/YAML error --> [DIE] croak "Failed to parse ..."
 1403: 	    v                                            |         |
 1404: 	+------------+  no develop: key --> carp --> DEFAULTS      |
 1405: 	| VALIDATE   |  bad name    --> carp, skip entry           |
 1406: 	+------------+  bad version --> carp, version 0            |
 1407: 	    |                                            |         |
 1408: 	    v                                            v         |
 1409: 	+------------+ <---------------------------------+         |
 1410: 	|   INJECT   |  add tools not already in develop           |
 1411: 	+------------+                                             |
 1412: 	    |                                                      |
 1413: 	    v                                                      |
 1414: 	+------------+ <-------------------------------------------+

 1416: 	+------------+
 1417: 	    |
 1418: 	    v
 1419: 	+--------+
 1420: 	| RETURN |  the cpanfile text; no file written;
 1421: 	+--------+  caller's $@, $! and $_ unchanged
 1422: 
 1423: The command-line tool adds one final step after RETURN: it writes
 1424: F<cpanfile> (default), prints the text (C<--dry-run>), or prints a diff
 1425: (C<--diff>).  A write error ends the program with a non-zero exit status
 1426: and leaves any existing F<cpanfile> unchanged.
